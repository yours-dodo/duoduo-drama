# 多多短剧（Duoduo Drama）

多多短剧是一个以 Agent 为核心的 AI 故事与短剧内容创作平台。项目希望把对话式创作、剧本处理、分镜制作、素材管理、视频合成和成片导出连接为连续、可追溯的创作流程，同时保留人工编辑、确认和回退能力。

> 当前项目仍处于产品规划和核心领域模型设计阶段，已初始化 TypeScript + pnpm monorepo 基础架构。

## 项目定位

当前阶段聚焦于**短剧内容创作闭环**，主要解决以下问题：

- 通过自然语言对话完成故事和剧本创作。
- 导入已有的单集或多集剧本继续创作。
- 将故事项目中的成果推进为独立的短剧项目。
- 按剧集、场景和镜头组织短剧制作过程。
- 管理人物、场景、道具、图片、视频、音频等创作素材。
- 使用 Agent 辅助生成分镜提示词、镜头内容和视频产物。
- 在上游内容发生变化时追踪对下游产物的影响。
- 支持人工检查、修改、确认、重新生成和最终导出。

剧组生产管理、拍摄现场管理、内容发行、投放运营和数据分析不属于当前阶段的核心范围，未来可在内容创作能力稳定后扩展。

## 产品形态

系统采用“统一 Agent 服务核心 + 多平台客户端”的产品形态：

```text
Web 工作台 ───────┐
Android 客户端 ───┤
iOS 客户端 ───────┼──→ 统一 Agent 服务 ──→ 创作流程、模型与业务数据
HarmonyOS 客户端 ─┘
```

职责原则：

- **Agent 服务**负责业务流程、Agent 编排、会话状态、任务执行、模型调用和通用工具调用。
- **客户端**负责用户界面，以及录音、相机、文件访问、系统通知和本地缓存等平台能力。
- 各客户端共享账号、项目、会话、任务和创作数据，不分别实现独立的 Agent 系统。
- 第一阶段优先建设 Agent 服务和 Web 工作台；移动端在服务端接口与业务流程稳定后接入。

当前工程基础栈为 Nuxt Web、NestJS Server 和 Hono Agent；数据库、队列和移动端框架尚未确定。

## 核心业务领域

产品包含两个相互独立的一级创作领域：

```text
创作系统
├── 故事创作
└── 短剧创作
```

### 故事项目

故事项目用于故事、剧情和剧本相关的对话式创作。

故事创作页面从纯对话框开始，并支持上传文件，包括已有的多集剧本。一个故事项目可以包含多个创作对话，各对话保留独立历史，同时共享项目上下文和已确认成果。

```text
故事项目
├── 多个创作对话
├── 上传文件
└── Agent 创作成果
    ├── 草稿成果
    └── 已确认成果
```

基本规则：

- 用户首次发送消息或上传文件时，系统可以自动创建故事项目。
- Agent 生成故事或剧本内容时，先形成草稿成果。
- 用户确认草稿后，该成果成为项目的当前有效版本。
- 对话消息属于交互记录，创作成果属于独立业务数据。
- 归档或删除对话不能删除已经保存的创作成果。
- 剧本文件的深度解析、内部结构和成果类型将在 Agent 与剧本模块的详细设计阶段确定。

### 从故事项目推进为短剧项目

故事项目和短剧项目是两个独立的领域对象。推进操作不会修改故事项目的类型，而是根据用户选择的成果版本创建一个新的短剧项目。

```text
故事项目中的已确认版本
          │
          │ 创建版本快照
          ▼
      新的短剧项目
```

推进规则：

- 短剧项目保存来源故事项目和来源版本信息，用于追溯。
- 短剧项目接收的是故事或剧本的版本快照，不是实时引用。
- 创建完成后，两个项目拥有独立的内容、状态、权限和版本历史。
- 故事项目后续修改不会自动影响短剧项目。
- 短剧项目内的修改不会回写故事项目。
- 一个故事项目可以根据不同版本或制作目标创建多个短剧项目。
- 删除或归档来源故事项目不能破坏已经创建的短剧项目。

### 短剧项目

短剧项目负责从故事或剧本开始，一直推进到短剧预览和导出。

短剧项目可以通过三种方式获得初始内容：

1. 从故事项目的指定版本创建快照。
2. 直接导入单集或多集剧本。
3. 在短剧项目内从故事或剧本开始创作。

无论内容来自哪里，短剧项目中的故事和剧本都是本项目自己的可编辑内容，并拥有独立的剧本编辑流程和版本历史。

## 短剧创作流程

短剧项目的完整创作流程为：

```text
故事
  ↓
剧本
  ↓
分镜
  ↓
素材准备与管理
  ↓
分镜提示词创作与分镜合成
  ↓
视频剪辑与合成
  ↓
短剧预览与导出
```

| 阶段 | 主要职责 |
| --- | --- |
| 故事 | 确定故事内容、人物、背景和情节走向 |
| 剧本 | 创作、导入和编辑单集或多集剧本 |
| 分镜 | 将剧本组织为场景、镜头和镜头顺序 |
| 素材准备与管理 | 准备并管理人物、场景、道具、图片、视频和音频素材 |
| 分镜提示词创作与分镜合成 | 创作镜头提示词，生成或组合分镜画面与镜头产物 |
| 视频剪辑与合成 | 编排镜头视频、配音、音乐、字幕和转场 |
| 短剧预览与导出 | 生成预览版本，完成确认并导出最终结果 |

该流程不是只能执行一次的刚性流水线：

- 直接导入剧本时，可以跳过故事阶段，从剧本阶段开始。
- 被跳过的故事阶段以后仍可补充，但不阻塞后续流程。
- 用户可以返回上游阶段继续修改内容。
- 上游修改不会自动删除或覆盖已有的下游内容。
- 系统需要记录上下游内容使用的具体版本和生成来源。
- 受影响的下游内容会进入“待检查”或“需要重新生成”等状态。
- 用户可以选择继续沿用、局部更新或重新生成。

## 核心内容层级

短剧项目采用统一的项目、剧集、场景和镜头层级：

```text
短剧项目
└── 剧集
    └── 场景
        └── 镜头
```

各层级的主要职责：

- **短剧项目**保存整部作品的故事方向、人物、风格、共享内容和总体进度。
- **剧集**是一集短剧的创作、制作和交付单位。
- **场景**组织同一时间、地点或连续叙事段落中的剧本和制作内容。
- **镜头**是提示词创作、素材引用、画面生成、视频生成和剪辑编排的基本单位。

多集短剧按剧集独立推进流程：

```text
短剧项目
├── 项目级人物、风格和共享内容
├── 第 1 集：视频剪辑与合成
├── 第 2 集：分镜提示词创作
└── 第 3 集：剧本编辑
```

因此，不同剧集可以并行工作并处于不同阶段。项目总体状态由各剧集状态聚合得出，不要求全部剧集同步前进。

独立短片也使用相同的内部模型，只包含一个剧集；客户端可以隐藏不必要的剧集层级，降低操作复杂度。

## Agent 与人工协作

系统采用 Agent 自动执行与人工控制相结合的创作方式。

### 自动运行

用户描述创作目标后，Agent 可以创建阶段任务并连续推进创作流程。在没有检查点或异常的情况下，流程可以自动进入下一阶段。

### 阶段检查点

用户可以在关键阶段设置确认点。Agent 到达检查点后暂停，等待用户确认、修改或补充信息。

### 人工编辑

用户可以随时暂停自动流程，进入对应阶段的编辑界面。人工编辑后的内容成为后续 Agent 任务的新输入。

### 恢复与重试

人工确认或修改后，Agent 可以从当前状态继续执行。单个阶段任务可以独立暂停、恢复、失败重试或重新执行，不需要重启整个项目流程。

### 任务与流程

创作流程实例负责阶段顺序、依赖关系、检查点和总体进度；Agent 任务负责执行具体工作、记录日志并生成产物。流程实例不是一个覆盖全部阶段的“总任务”。

## 团队、项目与权限

用户在团队空间中开展创作。项目支持两种可见范围：

- **团队项目**：团队成员可见，项目创建者和受邀协作者可编辑。
- **私人项目**：对其他普通成员隐藏，但团队管理员仍可查看和管理。

系统级权限角色保持简化：

| 身份 | 主要权限 |
| --- | --- |
| 管理员 | 管理团队和成员；查看、编辑并管理团队项目和私人项目 |
| 项目创建者 | 查看和编辑自己创建的项目；管理项目协作成员 |
| 项目协作成员 | 查看和编辑被邀请参与的项目 |
| 其他普通成员 | 查看团队项目，不可修改未参与的项目 |

编剧、分镜师、素材制作、剪辑师和审核人等属于业务分工或成员标签，不作为系统级权限角色。

管理员访问或修改私人项目、项目可见范围发生变化、协作成员发生变化时，都需要保留审计记录。

## 开发说明

项目要求 Node.js 22 或更高版本，以及通过 `packageManager` 声明的 pnpm 版本。首次开发先安装依赖：

```bash
pnpm install
```

常用命令：

```bash
pnpm dev
pnpm build
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
```

`pnpm dev` 并行启动 Nuxt Web（3000）、NestJS Server（3001）和 Hono Agent（3002）。可以使用 `pnpm --filter @duoduo/server dev` 等命令只启动单个 workspace。

主要代码目录：

```text
apps/web/       Nuxt Web 工作台
apps/server/    NestJS 业务服务
apps/mobile/    移动端预留目录，尚未加入 workspace
agent/          Hono Agent 服务
vendor/         仅限本地使用的外部参考项目
```

代码默认放在唯一负责它的项目内。只有两个以上项目真实复用同一稳定抽象时，才提取共享包。每个项目根目录的 `AGENTS.md` 记录该项目特有的职责、依赖边界、命令和测试要求。

## 贡献

项目仍处于设计初期。提交变更前请：

1. 阅读项目规划和剩余任务清单，确认变更符合当前业务边界。
2. 保持提交内容聚焦，避免混入无关重构或格式调整。
3. 为引入的新工具提供明确、可复现的开发和验证命令。
4. 检查是否误提交密钥、令牌、私钥或本地环境配置。
5. 在涉及用户界面或行为变化时附上截图、终端输出或其他验证证据。

提交信息应简洁并使用祈使语气，例如：

```text
feat: add episode catalog
docs: refine short drama workflow
```
