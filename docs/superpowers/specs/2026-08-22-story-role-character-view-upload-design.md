# 角色人物视图上传设计

## 目标

在角色编辑页默认折叠的“高级配置”中，于“典型台词”之后新增“人物视图”上传区。上传区使用固定 16:9 预览比例。图片上传后可以预览、替换或移除，并在保存角色后持久化；下次打开角色时继续显示已保存图片。

## 数据模型与接口

- 在 `StoryRoleAsset` 上新增可空的 `viewAssetId` 字段，并建立与项目 `Asset` 的独立关系；服务端输出同时新增可空的 `viewAsset` 元数据和短期下载地址。
- Prisma 模型同步增加 `StoryRoleAsset` 的人物视图关系、`Asset` 的反向关系以及按租户和资产 ID 查询的索引。迁移同时建立单列资产外键和租户复合外键，保持与角色封面相同的个人项目、团队项目隔离约束。
- 持久化仓储必须同步扩展行类型、创建和更新映射、锁定读取与列表读取的原生 SQL 投影、数据库行转换和审计摘要，确保普通读取、锁定读取和列表读取都返回同一字段。
- 扩展领域快照、创建默认值、更新 mutation、可变字段白名单、字段校验、HTTP DTO、错误映射、输出映射和 Web `StoryRoleAsset` 类型。
- 复用现有角色资产上传 URL、完成上传和下载 URL 流程；绑定时校验资产属于同一租户和项目、状态为 `uploaded`，并且内容类型为支持的图片格式。
- 更新角色保存请求，使 `viewAssetId` 在上传完成后随角色保存绑定；移除时提交 `null`。绑定失败和已绑定资产不可用使用人物视图专用错误，避免与封面错误混淆。
- 增加数据库迁移与领域、应用、仓储测试，覆盖默认空值、绑定、替换、移除、跨租户或跨项目资产拒绝、非图片资产拒绝、失效资产拒绝和并发版本校验。

## 资产生命周期与一致性

- 上传完成但尚未保存角色的图片作为普通项目资产保留。用户取消编辑时不绑定角色，也不自动删除图片；图片仍可在项目资产中复用，之后可以在未被引用时单独删除。
- 资产删除流程必须同时检查角色封面和人物视图引用。被任一活动角色引用的资产不得删除对象或转换为 `deleted`，而应返回明确的“资产正在使用”错误。
- 角色绑定与资产删除使用同一项目级写锁串行化。删除流程在持有项目写锁时检查引用，角色更新在同一锁内校验资产状态并写入引用，防止“检查后绑定”或“检查后删除”的竞态产生失效引用。
- 服务端读取已绑定人物视图时生成短期下载地址。若数据库中存在历史或异常的失效引用，返回人物视图不可用错误，不静默丢弃字段。

## 编辑页交互

- 人物视图区块位于默认折叠的“高级配置”内容中，在“典型台词”之后显示；高级配置收起时，人物视图也随父级内容隐藏。
- 预览容器使用 `aspect-ratio: 16 / 9`，图片使用 `object-fit: cover` 居中裁切显示。该比例只约束页面预览，不校验、不裁剪也不改写原始图片文件。
- 支持 JPG、PNG、WebP，沿用现有 20MB 上限。上传阶段显示进度，并禁用保存、归档、替换、移除等冲突操作；上传失败显示可重试错误。
- 新上传先绑定到本地草稿状态，点击“保存角色”才提交 `viewAssetId`；取消编辑不修改角色关联。
- 替换和移除只更新草稿关联，保持与角色封面一致的预览和保存语义。保存成功后刷新初始人物视图 ID 与文件元数据；保存冲突或失败时保留当前草稿和本地预览，允许用户重试。

## 边界与兼容

- 老角色没有人物视图时字段为 `null`，不影响现有角色列表、封面和人物深层特质数据。
- 页面重新加载时从服务端输出恢复已保存视图；人物视图的本地预览 URL 在组件卸载、替换或保存成功后释放，且与封面预览 URL 分别管理。
- 桌面和窄屏使用同一数据流，窄屏仅调整布局，不改变 16:9 比例。

## 验证

- 验证 Prisma 模型和迁移，并运行领域、更新用例、资产删除用例与 PostgreSQL 仓储测试，确认所有读取路径都保留 `viewAssetId`。
- 增加资产删除与角色绑定的竞态测试，确认项目级写锁下不会产生指向 `deleted` 资产的角色引用。
- 运行 Web 格式、类型和测试检查。
- 对角色编辑路由执行 smoke check，并验证高级配置默认折叠、展开后上传盒、空状态、上传中状态、错误状态和已保存图片的 DOM 结构。
