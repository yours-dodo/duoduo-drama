# 世界构成结构化编辑器

> 本设计中的“实体详情优先、关系作为页签”界面已被
> `2026-08-19-story-worldview-fact-graph-design.md` 替代。领域字段可继续复用，
> 但世界构成的主界面改为只读事实关系图与可编辑事实关系清单。

## 目标

为故事世界观页面的“世界构成”提供结构化编辑能力，使其成为 AI 上下文、RAG 检索和关系图共同使用的权威数据源。

结构化字段和显式关系是事实来源。富文本只负责补充难以拆成字段的叙述信息，不从富文本自动推断并持久化正式关系。

## 范围

首期实现 Web 端可编辑、可校验、可序列化的结构化原型，包括：

- 地点、组织、角色和规则四类世界要素的详情编辑；
- 要素之间的结构化关系编辑；
- 本地原型状态中的新增、修改和关系完整性校验；
- 为后续 Server 持久化、RAG 入库和关系图消费提供稳定数据边界。

首期不接入 Server、数据库、向量索引、Agent 或真实持久化，也不实现多人协作和版本历史。

## 编辑界面

世界构成继续使用左侧目录树。四个固定目录负责确定要素类型：地点、组织、角色、规则。目录可以展开或收起，目录下的信息项可以选择；每个目录提供新增当前类型要素的入口。

右侧区域由“详情”和“关系”两个页签组成。

### 详情

详情页签编辑当前要素的字段。通用字段包括：

- 名称：必填；同一类型内不可重名，不同类型可以重名，内部关联不依赖名称；
- 别名：可添加多个，供检索和名称归一化使用；
- 一句话摘要：必填，用于目录外的简要展示和 RAG 摘要块；
- 详细说明：可选富文本，用于承载无法稳定拆分为字段的叙述信息。

类型由要素所在目录决定，详情表单不提供任意改变类型的控件。不同类型显示不同的结构化字段：

- 地点：地点类型、上级地点、时代、环境特征；
- 组织：组织目标、权力范围、所在地；
- 角色：关联角色资产、在世界中的身份；
- 规则：适用范围、触发条件、产生效果、代价、例外。

角色不在世界构成中复制完整人设。角色要素通过稳定的角色资产 ID 引用“角色资产”模块，并只保存该角色在世界构成中的身份与关系。首期原型使用现有角色 ID；后续由 Server 保证跨模块引用完整性。

### 关系

关系页签维护独立的关系记录。每条关系由源要素、关系类型和目标要素组成：

```text
源要素 → 关系类型 → 目标要素
```

新增关系时默认把当前要素作为源要素，但源和目标都可以重新选择。当前要素的传入和传出关系都在该页签展示。关系记录引用稳定 ID，不保存名称副本；要素重命名不会破坏关系。

关系类型从项目关系类型注册表中选择，不把任意输入文本直接保存为谓词。注册表中的每种关系类型具有稳定 ID、显示名称以及可选的源类型和目标类型约束。用户可以登记新的项目关系类型；已有关系始终引用关系类型 ID，因此同义文案调整不会拆分图谱中的边类型。

## 数据模型

采用可区分联合类型表达世界要素，使通用字段与类型专属字段同时具备明确约束。

```text
WorldEntityBase
  id
  type
  name
  aliases[]
  summary
  description

LocationEntity.attributes
  locationType
  parentLocationId?
  era
  environment

OrganizationEntity.attributes
  purpose
  authority
  locationId?

CharacterEntity.attributes
  roleAssetId
  worldIdentity

RuleEntity.attributes
  scope
  trigger
  effect
  cost
  exceptions[]

WorldRelationType
  id
  label
  allowedSourceTypes[]?
  allowedTargetTypes[]?

WorldRelation
  id
  sourceEntityId
  relationTypeId
  targetEntityId
  description?
```

实体和关系分别保存。目录树由实体 `type` 派生，不维护第二份目录归属数据。

## 数据流

1. 用户从目录选择要素，编辑器读取对应实体及其传入、传出关系。
2. 用户修改字段时，界面更新本地草稿并显示未保存状态。
3. 保存时先执行实体字段和关系引用校验；校验成功后更新本地权威状态。
4. 关系图从实体和关系权威状态派生节点与边，不单独保存图形数据。
5. 后续接入 Server 后，保存动作改由 API 适配器提交，不改变组件使用的数据模型。

## AI、RAG 与关系图边界

RAG 为每个实体生成可独立更新的检索文档，内容由名称、别名、摘要、类型专属属性和详细说明组成，并携带项目 ID、实体 ID、类型和版本等元数据。

角色要素在建立 RAG 文档时解析其角色资产引用，把需要检索的角色摘要合并到索引文档，但不把复制结果写回世界构成实体。

关系图只读取 `WorldRelation` 生成边，并通过实体 ID 获取节点名称和类型。富文本中出现的关系可以由 AI 提议，但必须经过用户确认并转化为 `WorldRelation` 后才成为正式关系。

## 校验与错误处理

- 名称、一句话摘要以及类型专属字段中除上级地点、所在地和例外以外的字段为必填项；
- 上级地点、所在地和角色资产引用必须指向存在且类型正确的对象；
- 关系源、目标和关系类型必须存在，源与目标不能是同一个实体，并满足关系类型声明的类型约束；
- 项目内的关系类型显示名称不可重复；
- 删除仍被关系、上级地点或所在地引用的要素时阻止删除，并列出需要处理的引用；
- 保存失败时保留本地草稿和错误信息，不覆盖最后一次有效状态；
- 要素仅允许跨类型重名，所有引用和更新都使用稳定 ID。

## 组件边界

- 世界构成工作区负责目录选择和详情、关系页签切换；
- 实体详情编辑器负责通用字段与类型专属字段；
- 关系编辑器负责关系列表、源目标选择、关系类型登记和关系校验提示；
- 领域模型与校验函数保持框架无关，Vue 组件只消费其公开接口；
- 后续 Server API 通过单独适配器接入，不在组件中直接处理网络协议。

## 测试与验证

- 单元测试覆盖四种实体结构、目录派生、序列化和字段校验；
- 单元测试覆盖关系新增、关系类型约束、重命名不破坏引用、悬空引用和删除保护；
- 组件行为测试覆盖目录选择、详情编辑、类型专属字段、保存状态及详情/关系页签；
- 浏览器检查覆盖桌面和窄屏下的表单可读性、目录折叠和关系编辑；
- 运行 Web 测试、类型检查、生产构建、针对性 lint、格式检查和 `git diff --check`。

## 不在范围内

- 不允许用户创建第五种自定义要素类型；
- 不从富文本静默生成正式实体或关系；
- 不在世界构成中复制完整角色资产；
- 不在首期实现关系图拖拽布局、批量导入、自动合并或实体版本历史。
