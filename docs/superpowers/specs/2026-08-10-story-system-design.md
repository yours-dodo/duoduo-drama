# 故事系统 MVP 设计

**日期：** 2026-08-10

**状态：** 设计方向已确认，等待文档审阅

## 1. 决策摘要

第一阶段先建设独立的故事系统，不建设短剧制作流程。故事系统负责故事和剧本相关的对话式创作、成果管理和版本确认；短剧系统作为后续独立业务领域建设。

故事系统与短剧系统在业务模型上分开，但当前采用模块化单体实现，不立即拆成两个独立服务。两者只共享平台基础能力，并通过“已确认故事成果的版本快照”衔接。

Agent 是故事系统的执行能力，不是故事系统的权威数据源。Server 保存真实业务状态，Agent 接收明确的上下文并返回候选成果；候选成果必须经过 Server 保存和用户确认后，才能成为当前有效版本。

## 2. 第一阶段目标

用户能够完成以下最小闭环：

```text
创建故事项目
    ↓
创建或继续创作对话
    ↓
发送创作请求
    ↓
Agent 生成候选故事内容
    ↓
保存为草稿成果
    ↓
用户编辑并确认
    ↓
形成可追溯的有效版本
```

首批故事成果类型为：

- 故事创意
- 世界观设定
- 人物设定
- 故事大纲
- 剧本草稿

首版成果内容使用 Markdown 或纯文本保存。复杂的结构化剧本协议不属于本阶段范围。

## 3. 非目标

第一阶段明确不包含：

- 短剧项目、剧集、场景和镜头。
- 分镜、图片生成、视频生成、剪辑和成片导出。
- 故事系统与短剧系统的实时同步。
- 移动端应用。
- 多 Agent 协作和通用工作流市场。
- 复杂知识库、检索增强和长期记忆产品化。
- 故事系统的运营发行和投放能力。

文件和对象存储可以作为平台基础设施继续建设，但首版故事闭环不依赖复杂的素材管理流程。

## 4. 系统边界

```text
共享平台基础能力
├── 用户、团队和权限
├── 审计
├── 数据库和对象存储
├── @duoduo/ai
└── Agent Runtime

故事系统
├── 故事项目
├── 创作对话
├── 对话消息
├── 故事成果和版本
└── 故事生成请求

短剧系统（后续）
├── 短剧项目
├── 剧集
├── 场景
├── 镜头
├── 制作素材
└── 视频和成片
```

当前代码组织采用以下职责：

- `apps/server`：故事领域模型、权限、业务用例、持久化和客户端 API。
- `agent/`：故事生成、改写、分析等 Agent 工作流和模型配置。
- `packages/agent-runtime`：框架无关的 Agent 执行与 Harness 能力。
- `packages/ai`：模型 Provider 和生成协议适配。
- `apps/web`：故事创作工作台和 Server API 适配。
- `apps/admin`：平台运维能力，不参与故事创作主流程。

Web 只能调用 Server，不能直接调用 Agent。Agent 不能直接连接 Server 数据库，也不能自行修改故事项目。

## 5. 核心领域模型

### 5.1 StoryProject

故事项目是故事、剧情和剧本创作的容器，属于一个团队，拥有独立的可见范围、生命周期和并发修订号。

项目修订号只用于项目自身可编辑属性的并发控制，不替代故事成果版本号。

### 5.2 Conversation

创作对话是故事项目内独立保存的消息上下文。一个项目可以拥有多个对话；对话可以单独重命名、归档和读取历史。

对话归档不删除已经生成或确认的故事成果。归档对话不能继续追加用户消息。

### 5.3 Message

消息是不可变的追加记录，至少区分用户、Agent 和系统消息。消息只记录交互过程，不作为正式故事成果使用。

### 5.4 StoryArtifact

故事成果是可以独立编辑、确认、回退、引用和导出的业务对象。它拥有稳定身份和成果类型，并通过版本记录具体内容。

首版成果类型使用有限枚举，不允许 Agent 任意创建未知类型。成果标题和正文由 Server 做长度和格式校验。

### 5.5 StoryArtifactVersion

故事成果版本保存某一次完整内容快照，版本不可变。版本包含：

- 所属成果和版本序号。
- Markdown 或纯文本内容。
- 草稿、已确认或已放弃状态。
- 来源类型，例如用户编辑、Agent 生成或后续导入。
- 关联的生成请求或触发消息。
- 创建时间和创建者。

一个成果可以有多个已确认版本，但 `StoryArtifact` 维护一个当前有效版本指针。确认新版本或回退版本时，Server 原子更新该指针。

### 5.6 StoryGenerationRequest

故事生成请求表示一次明确的 Agent 生成意图，与触发消息分开保存。它保存不可变的输入快照、幂等键、处理状态和结果关联。

请求状态为：

```text
pending → processing → succeeded
                     └→ failed
```

同一个幂等键只能创建一个有效请求。失败请求可以重试，但重试必须产生可追溯的执行记录，并且不能重复追加原始用户消息。

## 6. 生成与确认流程

### 6.1 创建请求

用户发送消息时，Server 在一个事务中完成以下操作：

1. 校验用户对团队、故事项目和对话的权限。
2. 追加用户消息。
3. 保存本次请求的输入快照。
4. 创建 `StoryGenerationRequest`。
5. 保存幂等结果。

事务提交后，Server 才调用 Agent。这样即使 Agent 暂时不可用，用户消息和待处理请求仍然可恢复。

### 6.2 Agent 执行

Server 通过明确的 Agent 集成协议发送：

- 请求 ID 和幂等键。
- 租户、项目和对话的授权范围。
- 对话消息上下文。
- 当前有效的故事成果版本摘要。
- 用户本次创作目标。

Agent 返回经过协议约束的候选结果，包括成果类型、标题、正文和来源关联。模型输出属于不可信输入，不能直接成为数据库写入指令。

### 6.3 保存草稿

Server 验证 Agent 返回的成果类型、长度、关联项目和请求状态后，创建 `StoryArtifactVersion` 草稿，并将生成请求标记为成功。重复回调或重复重试必须通过请求 ID 和幂等键得到同一结果。

### 6.4 用户确认

用户可以编辑草稿，然后执行确认、放弃或继续修改：

- 确认：将草稿变为已确认版本，并更新成果的当前有效版本指针。
- 放弃：将草稿标记为已放弃，不影响当前有效版本。
- 编辑：创建新的用户编辑版本，保留原始 Agent 草稿的来源关系。
- 回退：将当前有效版本指针切换到历史已确认版本，不删除其他版本。

确认、放弃和回退都由 Server 负责权限校验、并发校验和审计记录。

## 7. Web 工作台范围

首版 Web 只需要支持故事创作主流程：

- 故事项目列表和创建。
- 故事项目基本信息编辑和归档。
- 项目内对话列表、对话切换和消息历史。
- 消息发送、生成中、失败和重试状态。
- 故事成果列表和成果类型筛选。
- 草稿编辑、确认、放弃和版本历史。

页面可以采用“左侧对话、中间消息、右侧成果”的工作台布局，但布局不是领域模型的一部分。加载、空数据、失败、无权限和禁用状态必须清晰呈现。

## 8. 错误、权限与审计

- Server 是唯一的权限判断入口；Agent 不重复实现团队和项目权限。
- Agent 调用必须有超时、幂等键和明确的失败映射。
- Agent 不可用时，请求保留为可恢复状态，不能伪装成成功。
- 归档项目或归档对话禁止继续产生新的故事成果。
- 项目、对话、成果和生成请求的跨租户访问都必须返回统一的不可访问结果。
- 生成请求、草稿确认、版本回退和失败重试需要保留审计关联。
- 日志不能记录凭证、完整敏感内容或未经过限制的模型输入输出。

## 9. 测试与验收

### 领域测试

- 项目和对话生命周期。
- 标题、内容和成果类型校验。
- 成果版本确认、放弃和回退。
- 归档对象禁止继续修改。
- 并发修订冲突。

### 应用和 HTTP 测试

- 创建项目、对话和消息。
- 消息与生成请求的原子创建。
- Agent 成功、超时、失败和重复回调。
- 草稿保存和用户确认。
- 跨团队、无权限和已归档对象访问。
- PostgreSQL 事务、幂等和审计行为。

### MVP 验收标准

一个用户可以在一个团队中创建故事项目，经过一次对话请求得到一份 Agent 草稿，编辑并确认该草稿，然后查看当前有效版本和历史版本；重复提交、Agent 失败和并发修改不会破坏项目状态。

## 10. 与短剧系统的后续衔接

短剧系统不直接读取故事系统的内部表或领域对象。后续通过显式的导出操作创建不可变故事快照，快照至少包含：

- 来源故事项目 ID。
- 来源故事成果 ID。
- 来源已确认版本 ID。
- 导出时的完整内容快照。
- 导出时间和操作者。

短剧系统创建自己的项目和内容版本，并保存来源快照信息用于追溯。故事系统后续修改不会自动覆盖短剧系统中的内容。

## 11. 后续实现顺序

1. 以现有故事领域和 Server 模块为基础，补充故事成果及版本模型。
2. 使用确定性 Mock Agent 跑通生成请求、草稿和确认流程。
3. 建设 Web 故事工作台。
4. 接入 `agent/` 的一个故事生成工作流。
5. 补充失败恢复、重试、审计和版本回退。
6. 以独立设计启动短剧系统。

在故事 MVP 验收前，不扩展短剧领域模型，也不把 Agent Runtime 的通用能力继续抽象成与故事业务无关的产品功能。
