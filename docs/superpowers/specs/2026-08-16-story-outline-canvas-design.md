# 故事大纲双模式画布设计

日期：2026-08-16  
状态：待用户确认

## 1. 目标

改造 `/stories/:id/outline` 的内容区，使其成为可操作的故事结构画布。画布提供两层选择：

- **时间轴**：横轴、纵轴、鱼骨图
- **世界构成**：逻辑图、思维导图

五种视图共享同一份大纲节点与关系数据。用户可以新增、编辑、删除节点，并通过拖拽调整节点位置；切换视图只改变布局，不复制或破坏大纲数据。

本阶段是前端交互原型，使用内置示例数据和浏览器内存状态，不接数据库或 Server API。

## 2. 范围与非目标

### 本阶段包含

- 仅在普通项目路由 `/stories/:projectId/outline` 实现，沉浸式大纲页复用同一组件结构。
- 顶部模式切换：`时间轴` / `世界构成`。
- 时间轴子视图：`横轴` / `纵轴` / `鱼骨图`。
- 世界构成子视图：`逻辑图` / `思维导图`。
- 示例节点、节点关系、节点选中态。
- 新增节点、编辑节点标题和摘要、删除节点。
- 节点拖拽调整画布位置。
- 新增节点、缩放、重置布局等画布工具。
- 右侧常驻 AI 聊天区继续由现有项目壳层负责，不被画布覆盖。

### 本阶段不包含

- 数据库表、API、自动保存和多人协作。
- Agent 生成大纲或自动改写节点内容。
- 章节正文编辑、故事线/章节/场景卡独立路由。
- 任意节点之间的自由连线编辑。
- 复杂画布能力：框选、多选、快捷键系统、撤销/重做、导出图片。

## 3. 视觉与布局方向

画布沿用故事项目编辑页的深色编辑室主题：近黑画布、米白文字、橙色当前动作和焦点、低对比度细线。画布不新增渐变、玻璃拟态或厚重阴影。

页面结构：

```text
项目 Header：世界观 / 角色资产 / 大纲 / 故事正文
┌─────────────────────────────────────────────┐
│ 大纲标题与说明                         AI 对话区 │
│ [时间轴] [世界构成]                               │
│ [横轴] [纵轴] [鱼骨图]       [新增] [缩放] [重置] │
│                                                 │
│                 SVG + HTML 画布                 │
│             节点 / 关系线 / 选中态               │
└─────────────────────────────────────────────┘
```

主画布使用可横向、纵向滚动的区域。节点采用矩形编辑卡，不使用圆角卡片；选中节点使用橙色细线和轻微橙色外发光作为唯一主状态。关系线使用低对比度 hairline，箭头和标签在 hover/选中时提高对比度。

节点的最小可操作尺寸保持在 44px 以上。移动端不强行压缩完整画布，而是允许画布横向滚动；工具栏可换行，编辑面板变成底部浮层。

## 4. 数据模型

原型阶段在 `StoryProjectView.vue` 的 outline 子模块中维护局部响应式状态，模型保持可迁移到 API 的形状：

```ts
type OutlineNodeType = 'event' | 'character' | 'conflict' | 'chapter';

type OutlineNode = {
  id: string;
  title: string;
  summary: string;
  type: OutlineNodeType;
  parentId?: string;
  order: number;
  lane?: string;
  position?: { x: number; y: number };
};

type OutlineEdge = {
  id: string;
  source: string;
  target: string;
  label?: string;
};
```

设计约束：

- 节点 ID 稳定且唯一；视图切换不得重新生成 ID。
- `order` 表示故事推进顺序，`position` 只表示当前视图中的人工位置。
- `parentId` 用于思维导图的层级关系；`edges` 用于逻辑图和鱼骨图的因果关系。
- 删除节点时同时删除以该节点为 source 或 target 的关系，避免画布出现悬空线。
- 新增节点默认插入当前选中节点之后；没有选中节点时追加到末尾。
- 空标题不允许提交；摘要可为空。

## 5. 视图与布局

### 5.1 时间轴

时间轴模式展示故事推进顺序。节点按 `order` 排列，`lane` 负责多条叙事线或角色线。

- **横轴**：x 表示时间/顺序，y 表示 lane；适合快速看节奏和并行线。
- **纵轴**：y 表示时间/顺序，x 表示 lane；适合窄屏和长篇结构浏览。
- **鱼骨图**：一条主轴表示故事主线，事件节点沿主轴排列；相关冲突、原因和结果挂在主轴上下两侧。

时间轴视图的节点连线默认依据相邻 `order` 或显式 `edges` 生成，避免用户需要先编辑复杂关系才能看到可用画布。

### 5.2 世界构成

世界构成模式展示故事中的人物、地点、组织、规则与关系，不强调线性顺序。

- **逻辑图**：以有向关系为主，节点按照依赖、因果和条件组织；边可以展示关系标签。
- **思维导图**：以故事核心为中心，按照 `parentId` 向外分层；首层分支使用角色、冲突、世界和剧情等类型。

逻辑图和思维导图使用固定的确定性布局函数。相同数据和相同视图在重置布局后得到相同结果，便于原型阶段测试和后续服务端复现。

## 6. 交互设计

### 模式与视图切换

- 第一层使用两个无背景文本 Tab：`时间轴`、`世界构成`。
- 第二层只显示当前模式的子视图：
  - 时间轴：横轴、纵轴、鱼骨图
  - 世界构成：逻辑图、思维导图
- 当前项使用橙色文字和下边框，其他项只有 hover 反馈。
- 切换视图不清空选中节点；如果当前布局不支持某种位置，使用布局函数重新计算视觉位置。

### 节点操作

- 点击节点：选中节点，并在节点附近显示轻量操作条。
- 双击节点或点击编辑：打开节点编辑浮层，可修改标题、摘要和类型。
- 新增节点：打开同一编辑浮层；保存后插入节点并自动选中。
- 删除节点：需要一次确认；删除关系后保留其余节点。
- 拖拽节点：只修改当前视图的 `position`，不改变故事顺序和关系数据。
- 点击画布空白处：取消节点选中和操作条。

### 画布工具

- `新增节点`：始终可用，满足最小触控尺寸。
- `缩小` / `放大`：调整画布比例，限制在 0.6x–1.8x。
- `重置布局`：清除当前视图的手动位置并运行对应确定性布局。
- 工具按钮使用无背景 icon button，提供可见 tooltip 和 `aria-label`。

### 编辑状态

- 原型只在内存中保存，切换路由或刷新页面会恢复示例数据。
- 保存成功后显示短暂的 `已更新` 状态，不伪装成已持久化到服务器。
- 删除和空标题错误使用可见文本提示，同时保留 `aria-live` 状态。

## 7. 组件边界

实现时将 outline 画布拆成以下职责明确的 Vue 组件或局部模块：

- `StoryOutlineWorkspace`：outline 页面组合、模式/视图状态和工具栏。
- `StoryOutlineCanvas`：SVG 关系线、HTML 节点层、缩放和拖拽事件。
- `StoryOutlineNodeEditor`：新增/编辑表单、校验和提交。
- `story-outline-layout.ts`：五种布局的纯函数，不依赖 Vue 或 DOM。
- `story-outline-types.ts`：节点、边、视图模式和布局结果类型。

现有 `StoryProjectView.vue` 继续负责项目模块路由和通用资产页头；右侧 `StoryChatPanel` 不移动到 outline 内部。

## 8. 可访问性与响应式

- 节点使用可聚焦按钮或等价语义元素，不把 SVG 图形作为唯一交互入口。
- 节点标题、类型和摘要通过可访问名称暴露。
- 拖拽之外提供“编辑”按钮，避免依赖精细指针操作。
- 颜色不是唯一状态线索，选中节点同时使用边框和操作条。
- 画布缩放不影响工具栏和编辑表单的可访问字号。
- 在 `prefers-reduced-motion` 下关闭节点位置过渡。

## 9. 测试与验收

### 单元测试

- 五种布局对同一份节点数据输出稳定结果。
- 节点 ID、边引用和删除级联逻辑正确。
- 新增节点的 order、parentId 和默认位置符合规则。
- 空标题被拒绝，合法标题可保存。

### 页面验收

- `/stories/:id/outline` 默认进入“世界构成 / 思维导图”。
- 五种视图均可切换，切换后节点和关系仍保留。
- 新增、编辑、删除、拖拽均有可见反馈。
- 普通项目与沉浸式项目路由都能渲染同一 outline 画布。
- 右侧 AI 聊天区全高、无圆角，并且不因画布切换消失。
- 根 `/stories` 页面和其他三个项目模块不受影响。
- 至少检查桌面宽度与窄屏宽度；无浏览器自动化时使用 SSR/HTTP smoke 作为补充证据，并明确记录限制。
