# 世界构成目录树

## 目标

将故事世界观页面的“世界构成”左侧区域从扁平要素列表调整为目录树，使要素类别与具体信息项形成明确层级。

## 信息架构

世界构成包含四个一级目录，目录下放置对应的信息项：

- 地点
  - 雾城
- 组织
  - 档案管理局
- 角色
  - 林遥
- 规则
  - 记忆规则

四个目录默认展开，并允许用户独立收起或展开。目录本身只承担分类与导航作用；具体信息项仍是可选择的世界要素。

## 数据模型

在 Web 端原型数据中使用“目录包含要素”的嵌套结构，每个目录包含稳定的 `id`、显示名称和要素数组。要素继续保留稳定 `id`、名称、类型与描述。

界面需要扁平访问全部要素时，从目录数据派生扁平列表，避免同时维护互相可能失配的两份要素数据。当前原型不新增后端接口或持久化逻辑。

## 界面与交互

- 左侧标题由“世界构成 / 要素”调整为“世界构成 / 目录”。
- 目录行沿用“设定文档”已有的折叠箭头、层级连线和紧凑编辑台风格。
- 信息项行只显示名称，避免在狭窄目录中重复展示类型和长描述。
- 点击信息项后更新当前选中要素，右侧继续显示其类型、名称和描述。
- 右侧关系区及现有关系结构保持不变；涉及该规则的关系文本同步使用“记忆规则”。
- 保留当前默认选中的“林遥”，避免改变页面初始行为。

## 可访问性

- 目录折叠按钮提供 `aria-expanded` 与对应内容容器的 `aria-controls`。
- 当前信息项继续通过选中样式和 `aria-current` 表达。
- 所有目录与信息项均使用原生按钮，可通过键盘聚焦和触发。

## 验证

- 添加数据层测试，确认四个目录及其信息项映射准确，并确认扁平派生结果不丢失要素。
- 运行 Web 测试、Web 类型检查和 Web 构建。
- 在桌面宽度与窄屏宽度检查目录展开、收起、选择和右侧详情更新。
- 运行 `git diff --check`，确保没有空白字符问题或无关改动。

## 不在范围内

- 不实现新增、删除、拖拽排序或重命名目录与信息项。
- 不改变关系拓扑、关系筛选逻辑或右侧关系布局。
- 不新增依赖，不连接 Server 或 Agent 服务。
