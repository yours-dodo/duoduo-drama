# 故事小说书库与编辑入口设计

## 背景

故事模块的入口需要先展示用户已经创作的小说，再让用户进入某一本小说的编辑页。当前 Web 已经提供两个对应路由：`/app/stories` 和 `/app/stories/[projectId]`；Vue Story 工作区也已经具备项目列表、新建项目、项目详情和成果编辑能力。本次工作将入口页从当前的双栏项目清单调整为小说书库视觉，同时保持现有编辑工作台边界。

## 目标

- 进入故事模块后，以响应式书库网格展示已创作的小说。
- 每个作品单元上方展示视觉缩略图，下方展示小说名。
- 如果项目数据提供封面地址，优先使用真实封面；没有封面时使用稳定的默认视觉。
- 点击作品单元进入 `/app/stories/[projectId]` 编辑页。
- 保留新建小说入口，并在创建成功后进入新小说编辑页。
- 保持现有登录、团队权限、加载、错误和空状态处理。

## 非目标

- 本次不增加封面上传、替换、裁切或删除能力。
- 本次不修改后端数据库、资产模型或资产绑定接口。
- 本次不改变故事成果、版本确认和草稿编辑流程。
- 本次不把项目资产中的任意图片自动猜测为封面。

## 方案

采用前端可选字段方案。`StoryProject` 类型预留 `coverUrl?: string | null`，列表渲染时根据该字段选择图片或默认视觉。当前 Server API 没有返回该字段，因此现阶段所有没有封面地址的项目使用默认视觉；未来 Server 开始返回 `coverUrl` 后，Web 无需改变卡片决策逻辑即可显示真实封面。

不采用“取第一个图片资产作为封面”，因为资产列表中的文件没有用途语义，顺序也不能证明某张图是书封面。封面绑定属于后端领域数据，应该在未来单独设计和实现。

## 页面结构

### 小说书库页

路由：`/app/stories`

页面继续由 Astro 路由壳和 `StoryApp.vue` 组成。`StoryApp` 在无 `projectId` 时进入 catalog 模式：

1. 顶部保留故事工作区标题、当前团队和切换工作台入口。
2. 主内容使用作品网格，每个作品单元包含封面区域、书名、状态和更新时间。
3. 封面使用稳定的 3:4 比例，避免图片、默认视觉或加载状态改变网格尺寸。
4. 作品单元整体使用链接或等价键盘可操作元素，点击后进入对应项目路由。
5. 网格在窄屏下降为两列或单列，书名和状态不发生遮挡或溢出。
6. 新建故事保留在书库页的明确入口；创建操作继续调用 `createStoryProject`。

卡片下方只放作品识别和管理信息。小说名不叠加在封面图上，以保证不同封面、默认视觉和移动端都能稳定阅读。

### 默认视觉

默认视觉不依赖随机数、远程图片或项目内容中的未定义字段。它使用项目在列表中的稳定视觉变体或已有设计 token 生成可识别的抽象封面，并统一保留同一比例、边框和层级。默认视觉只承担“没有封面时不留空白”的职责，不冒充真实小说封面。

### 小说编辑页

路由：`/app/stories/[projectId]`

本次保持现有编辑页结构和行为：加载项目及故事成果、选择成果、编辑草稿、保存新版本、确认或丢弃草稿。列表卡片只负责入口，不在编辑页增加封面管理控件。

## 数据与组件边界

- `apps/web/src/workspaces/story/story-api.ts`：为 `StoryProject` 预留可选 `coverUrl` 类型，不深度依赖 Server 内部类型。
- `apps/web/src/workspaces/story/StoryApp.vue`：负责 catalog 网格、封面回退选择、项目跳转和已有列表状态；project 模式沿用现有逻辑。
- `apps/web/src/styles/workspace.css`：增加书库网格、封面比例、默认视觉、标题和元信息样式；尽量替换 catalog 专用旧布局，避免影响 drama 工作区和编辑页样式。
- Astro 路由和 `story-api` 请求路径保持不变。

封面渲染需要同时处理两个回退情况：`coverUrl` 为空，以及图片加载失败。图片失败时应切换到默认视觉，并避免显示破损图片图标。该回退状态属于卡片局部状态，不应污染项目数据或改变 Server 权威状态。

## 交互与状态

- loading：继续显示工作区加载状态，网格未就绪前不渲染不完整卡片。
- ready + 有项目：显示书库网格。
- ready + 无项目：显示空状态和新建入口，说明如何开始第一部小说。
- error：继续显示错误信息和重新加载操作。
- auth-required：继续提供登录入口。
- 创建中：禁用创建提交，避免重复创建；成功后跳转新项目编辑页。
- 图片加载失败：当前卡片降级到默认视觉，不触发全页错误。
- 已归档项目：仍可从列表进入编辑页，但状态明确显示为已归档；是否允许修改继续由项目接口返回的 `canEdit` 决定。

## 可访问性与响应式要求

- 作品入口必须具有可见焦点样式和清晰的可访问名称，名称至少包含小说名。
- 封面图片有真实地址时使用小说名作为 `alt`；默认视觉使用空 alt 或由相邻标题提供语义，避免重复朗读。
- 不能只依赖颜色区分进行中和已归档状态。
- 使用稳定的 `aspect-ratio` 和网格约束，避免图片加载导致布局位移。
- 在桌面宽度下优先使用多列书库，在窄屏下减少列数并保证书名完整显示。

## 测试与验证

- Story API 类型/适配测试覆盖有 `coverUrl`、空 `coverUrl` 和字段缺失三种输入。
- Story 工作区测试覆盖：列表项目点击生成正确编辑页路径；无封面使用默认视觉；图片错误切换默认视觉；空列表仍可创建项目。
- 运行 `pnpm --filter @duoduo/web typecheck`、`pnpm --filter @duoduo/web test` 和 `pnpm --filter @duoduo/web build`。
- 浏览器检查 `/app/stories` 的桌面和窄屏布局，并检查 `/app/stories/[projectId]` 的入口跳转不影响现有编辑页。
- 完成前运行 `git status`、`git diff` 和 `git diff --check`，确认只包含本次设计文档或明确的实现文件。

## 后续封面能力

未来如果支持封面上传，需要由 Server 定义项目封面与资产的绑定关系，并在项目查询输出中返回可访问的封面 URL 或受控读取地址。上传、替换、权限校验和对象存储生命周期应单独设计，不由本次 Web 列表通过猜测资产来承担。
