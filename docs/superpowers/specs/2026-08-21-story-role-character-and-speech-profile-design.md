# 角色详情人物内核与声音表达重构设计

日期：2026-08-21

状态：已确认，待实施计划

## 背景

当前角色编辑页同时提供角色分类、角色顺序和戏份三个相近的叙事重要性字段，
但缺少决定角色行为一致性和对白辨识度的内在欲望、恐惧与底线、角色弧光及
声音表达信息。`角色顺序` 的“一号、二号、三号”不能明确表达番位、视角或
出场顺序；`戏份` 又混合了角色重要性与出场频率；`阵营` 中的“立场变化”则把
当前状态与变化过程放在了同一维度。

本次重构以角色详情本身为边界，按照 LLM 理解角色时的信息增益重新组织字段，
但不在本次把角色资产接入 Agent 上下文或修改生成提示词。

## 目标

- 删除或改造低信息量、语义重复和维度混杂的角色字段。
- 让角色详情明确表达人物性格、行动动机、行为边界和变化轨迹。
- 新增可稳定描述角色语速、句式、用词、口癖、脏话、玩梗、比喻、结巴及
  对不同对象表达差异的声音与表达资料。
- 让语言习惯同时包含频率、触发条件、排除条件和例句，避免把单一特征机械地
  应用到每句台词。
- 保持角色编辑页可逐步填写；除名称外，新字段允许为空。
- 保留角色封面、UUID、乐观锁、个人/团队项目授权和归档语义。

## 非目标

- 不把角色资料接入 Agent 请求、提示词、检索或上下文权重计算。
- 不选择或绑定具体 TTS Provider 的 voice ID。
- 不在本次建立角色关系图或独立的关系子资源。
- 不实现 AI 自动补全、自动生成台词样例或图片反向解析外观。
- 不建立角色版本历史，也不改变现有整张角色资产的保存与 revision 边界。

## 方案选择

采用“精简基础元数据 + 高信息量人物内核 + 结构化声音表达”的平衡方案。

未采用以下方案：

- 只增加一个自由文本“说话方式”：填写成本低，但数据质量和角色间一致性无法
  保证，LLM 容易过度使用脏话、口癖或结巴等醒目特征。
- 为每种语言现象建立独立字段：表达精确，但表单过长，也无法覆盖新的语言习惯。
- 完整人物圣经：关系图、经历时间线、秘密系统和多套场景语态超出当前角色编辑页
  的首轮重构范围。

## 字段决策

### 删除

| 当前字段 | 决策 | 理由 |
| --- | --- | --- |
| `narrativeOrder` / 角色顺序 | 从页面、领域快照和 API 移除 | 与叙事定位、出场频率重复，且“一号”等值语义不明确 |

### 保留或改造

| 当前字段 | 新字段或展示名 | 决策 |
| --- | --- | --- |
| `name` | 角色名称 | 保留并继续必填 |
| `category` | 叙事定位 | 保留现有主角、核心角色、配角、背景角色四档 |
| `occupation` | 身份 / 职业 | 保留 |
| `gender` | 性别 | 保留，但在页面中作为次要基础信息展示 |
| `camp` | 当前阵营 | 仅表达当前状态，选项改为主角方、对立方、中立、未明确 |
| `prominence` | `appearanceFrequency` / 出场频率 | 改为高频、中频、低频、仅被提及，不再表达角色重要性 |
| `summary` | `personalityCore` / 性格内核 | 明确填写核心性格、价值观、缺陷和人物反差 |
| `desire` | `externalGoal` / 外在目标 | 明确填写角色在剧情中主动追求的结果 |
| `mainlineRelation` | 与主线关系 | 保留 |
| `functions` | 剧情功能 | 保留字符串数组和用户顺序 |
| `coverAssetId` | 角色封面 | 保留现有 Asset 绑定语义 |

### 新增人物内核字段

| 字段 | 展示名 | 含义 |
| --- | --- | --- |
| `internalNeed` | 内在欲望 | 角色真正需要但未必愿意承认的情感或心理需求 |
| `fearsAndBoundaries` | 恐惧与底线 | 最害怕失去或面对的事，以及无论如何不会跨越的行为边界 |
| `characterArc` | 角色弧光 | 初始状态、触发变化的原因和最终状态 |

`当前阵营` 不再包含“立场变化”。涉及阵营改变的内容写入 `角色弧光`，例如
“初期为了自保加入对立方，中段发现真相，最终选择帮助主角”。

## 声音与表达模型

声音与表达资料作为一个随角色整体更新的 `speechProfile` 值对象保存。它不需要
独立查询、权限或 revision，因此不拆成子表；持久化使用 JSONB，领域层和 DTO
负责完整结构校验。

```ts
interface StoryRoleSpeechProfile {
  summary: string;
  pace: '缓慢' | '正常' | '偏快' | '急促' | '随情绪变化';
  sentenceStyle: '碎句为主' | '短句为主' | '长短混合' | '长句为主';
  defaultTones: string[];
  vocabularyStyles: string[];
  habits: StoryRoleSpeechHabit[];
  audienceStyles: StoryRoleAudienceSpeechStyle[];
  prohibitions: string[];
  dialogueExamples: StoryRoleDialogueExample[];
}

interface StoryRoleSpeechHabit {
  type:
    | '语气词'
    | '口头禅'
    | '脏话'
    | '玩梗'
    | '比喻'
    | '夸张'
    | '反问'
    | '重复'
    | '结巴'
    | '语病/错句'
    | '自我纠正'
    | '其他';
  description: string;
  frequency: '偶尔' | '经常' | '高频';
  triggers: string[];
  exclusions: string[];
  examples: string[];
}

interface StoryRoleAudienceSpeechStyle {
  audience: string;
  description: string;
}

interface StoryRoleDialogueExample {
  situation: string;
  emotion: string;
  audience: string;
  line: string;
}
```

`defaultTones` 只接受以下值：`平静`、`温和`、`冷淡`、`热情`、`强势`、
`讽刺`、`谨慎`、`讨好`。`vocabularyStyles` 只接受以下值：`口语化`、
`书面化`、`粗俗`、`文雅`、`网络化`、`专业化`、`方言化`、`年代化`。

空声音表达资料使用确定的非空结构：

```ts
const EMPTY_STORY_ROLE_SPEECH_PROFILE: StoryRoleSpeechProfile = {
  summary: '',
  pace: '正常',
  sentenceStyle: '长短混合',
  defaultTones: [],
  vocabularyStyles: [],
  habits: [],
  audienceStyles: [],
  prohibitions: [],
  dialogueExamples: [],
};
```

### 字段语义

- `summary`：一句话声口，例如“语速快、句子短，喜欢反问和生活化比喻，嘴损
  但很少真正爆粗”。
- `pace`：角色默认语速；具体场景和情绪可以临时覆盖。
- `sentenceStyle`：默认句子长度与节奏，不把反问、比喻等修辞混入该字段。
- `defaultTones`：默认交流姿态，例如平静、温和、冷淡、热情、强势、讽刺、
  谨慎、讨好，最多选择两项。
- `vocabularyStyles`：用词范围，例如口语化、书面化、粗俗、文雅、网络化、
  专业化、方言化、年代化，最多选择三项。
- `habits`：可重复的语言习惯；脏话、玩梗、比喻、结巴和错句统一使用该结构。
- `audienceStyles`：面对亲近者、陌生人、上级、敌人或其他对象时的表达变化。
- `prohibitions`：角色不会采用的表达方式，例如“不直接说我爱你”。
- `dialogueExamples`：带场景、情绪和对象的典型台词，作为最直接的语言风格样本。

### 语言习惯规则

- 不提供“总是”频率，避免一个特征占满所有台词。
- `脏话` 必须描述程度或实际词汇，并可通过排除条件限制对象和场景。
- `玩梗` 应描述梗的来源或范围，不能只记录“喜欢玩梗”。
- `比喻` 应描述偏好的意象领域，例如厨房、动物、商业或游戏。
- `结巴`、`重复`、`语病/错句` 应描述具体表现和触发条件，不能只使用布尔值。
- 例句用于展示表达模式，不作为角色经历或剧情事实。

## 页面信息架构

角色封面继续位于编辑页左侧。右侧表单按以下顺序分为四组：

```text
基础信息
  角色名称、身份/职业、性别、叙事定位、出场频率、当前阵营

人物内核
  性格内核、外在目标、内在欲望、恐惧与底线、角色弧光

叙事关系
  与主线关系、剧情功能

声音与表达
  说话风格概述、语速、句式节奏、默认语气、用词风格
  表达习惯、面对不同对象时、表达禁区、典型台词
```

基础信息使用紧凑网格。人物内核与叙事关系使用多行文本。声音与表达中的基础
选择保持紧凑；表达习惯、对象差异和典型台词使用可添加、编辑和删除的重复项。
所有分组保持在同一角色编辑路由和同一个保存动作中，不引入二级页面或独立草稿。

## 交互规则

- 新增文本和列表默认为空；语速默认为“正常”，句式节奏默认为“长短混合”。
  未填写的可选内容不显示验证错误，也不阻止保存。
- 表达习惯新增时默认频率为“偶尔”，但必须填写类型和具体描述后才能保存该条。
- 对象差异必须同时填写对象和描述；空白的新建项不进入请求。
- 典型台词必须填写台词正文；场景、情绪和对象允许为空。
- 重复项保持用户排序，并提供明确的上移、下移按钮；本次不增加拖动排序。
- 保存继续使用角色整体 `expectedRevision`；任一字段变化统一递增 revision。
- 冲突、网络失败、封面上传和归档状态沿用现有页面语义。
- 窄屏按分组纵向排列，重复项内部字段不得造成水平滚动。

## 校验与限制

- `personalityCore`、`characterArc`、`mainlineRelation`：各最多 2,000 字符。
- `externalGoal`、`internalNeed`、`fearsAndBoundaries`、`speechProfile.summary`：
  各最多 1,000 字符。
- `defaultTones` 最多 2 项；`vocabularyStyles` 最多 3 项；服务端去除空项并去重。
- `habits` 最多 12 条；每条描述最多 500 字符，触发和排除条件各最多 5 项，
  每项最多 100 字符，例句最多 3 条且每条最多 300 字符。
- `audienceStyles` 最多 8 条；对象最多 100 字符，描述最多 500 字符。
- `prohibitions` 最多 10 条，每条最多 200 字符。
- `dialogueExamples` 最多 8 条；场景、情绪和对象各最多 100 字符，台词最多
  500 字符。
- Web 提供相同的即时限制，Server 和领域模型仍是权威校验边界。
- 所有文本修剪首尾空白；数组去除空项并按首次出现顺序去重。

## 数据迁移与兼容性

- 将 `summary` 列重命名为 `personality_core`，保留已有文本。
- 将 `desire` 列重命名为 `external_goal`，保留已有文本。
- 新增 `internal_need`、`fears_and_boundaries`、`character_arc`，默认空字符串。
- 将 `prominence` 重命名为 `appearance_frequency`，并迁移现有值：
  `核心`、`高频` → `高频`，`低频` → `低频`，`背景` → `仅被提及`。
- `appearance_frequency` 新默认值为 `低频`；角色分类不再隐式决定出场频率。
- 将 `camp = 立场变化` 迁移为 `未明确`，避免猜测角色当前所属阵营；原始变化
  语义无法可靠恢复，不自动写入角色弧光。
- 删除 `narrative_order`。迁移前测试固定验证已知取值均可处理；该字段不迁移到
  其他高权重字段，避免把模糊番位解释成人物语义。
- 新增 `speech_profile JSONB NOT NULL`，默认写入完整空结构，而不是 `null`。
- 角色更新 API 采用新的字段名，不同时支持新旧字段双写；Web、Server 和 migration
  在同一变更中切换。

## API 与领域边界

角色创建、更新和输出契约增加人物内核字段与 `speechProfile`，移除
`narrativeOrder`、`summary`、`desire` 和 `prominence`。领域模型负责：

- 校验叙事定位、当前阵营、出场频率和声音表达枚举。
- 深度复制、修剪和规范化 `speechProfile`，防止调用方修改内部快照。
- 比较嵌套结构并仅在真实变化时递增 revision。
- 将审计摘要限制为角色名称、叙事定位、出场频率和 revision，不记录长文本、
  习惯内容或完整台词样例。

角色列表继续返回完整角色资产以保持现有 Web 适配方式。本次不另建精简列表 DTO；
若角色数量和响应体积以后成为实际问题，再增加列表投影。

## 测试策略

### Server 与领域

- 新字段创建、恢复、更新、修剪、去重、深度复制和 revision 变化。
- 语言习惯、对象差异、禁区和台词样例的正常、边界与非法输入。
- `立场变化` 和旧戏份值的数据迁移映射。
- DTO 拒绝已移除的 `narrativeOrder`、`summary`、`desire` 和 `prominence`。
- PostgreSQL 迁移保留性格内核与外在目标已有文本，并满足新 CHECK 约束。
- 个人项目、团队项目、授权、审计、封面绑定和归档行为保持不变。

### Web

- 编辑页不再显示角色顺序。
- 叙事定位、出场频率和当前阵营使用新语义与选项。
- 人物内核字段可以加载、修改、保存并在刷新后恢复。
- 表达习惯、对象差异、禁区和典型台词支持添加、删除、排序及限制提示。
- 保存请求使用新契约并携带完整 `speechProfile` 和 `expectedRevision`。
- 加载、失败、保存冲突、封面上传和归档状态没有回归。
- 桌面与窄屏下四个分组清晰，重复项没有水平溢出。

## 验收标准

- 目标角色编辑页不再出现“角色顺序”。
- 页面只使用“叙事定位”表达角色重要性，只使用“出场频率”表达出现频率。
- 当前阵营不再包含“立场变化”。
- 用户可以分别填写性格内核、外在目标、内在欲望、恐惧与底线和角色弧光。
- 用户可以描述角色语速、句式、默认语气、用词、表达习惯、对象差异、表达禁区
  和带情境的典型台词。
- 脏话、玩梗、比喻、结巴和错句等习惯可以表达频率、触发、排除和例句。
- 保存、刷新、并发冲突、个人/团队权限、封面和归档行为保持正确。
- 相关 migration、Server/Web 测试、typecheck、lint、格式检查及桌面/窄屏浏览器
  验证通过。
