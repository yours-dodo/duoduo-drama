# 世界构成事实关系图编辑器

> Server 持久化、数据库表、版本快照和实施边界见
> [故事世界观持久化与数据库表设计](../../../2026-08-20-story-worldview-persistence-design.md)。

## 设计结论

世界构成以“实体之间已经成立的事实关系”为主编辑对象，而不是以实体属性表单为主。

页面保留地点、组织、角色和规则四类实体目录。主工作区由只读事实关系图和可编辑事实关系清单组成；实体属性改由抽屉编辑。Ontology 与事实使用同一套图数据表达，但通过语句类型保持逻辑分层。

本设计替代 `2026-08-18-story-worldview-structured-editor-design.md` 中“实体详情优先、关系作为页签”的界面方案。上一版的实体字段、稳定 ID 和引用完整性原则继续有效。

## 目标

- 让创作者首先看到世界实体之间已经成立的关系；
- 让关系图、AI 上下文和 RAG 检索消费同一套结构化事实；
- 让 Ontology 约束关系事实，但不把 Ontology 定义混入默认事实图；
- 保留实体结构化属性和富文本补充说明，但不让它们占据关系主工作区；
- 为后续 Server 持久化、关系推理、索引和版本管理提供稳定数据边界。

## 信息架构

### 左侧：世界要素目录

地点、组织、角色和规则是固定目录，目录下显示对应实体：

```text
地点
  雾城
组织
  档案管理局
角色
  林遥
规则
  记忆规则
```

点击目录实体会选中对应图节点，并筛选其传入和传出关系。实体旁提供“编辑属性”入口，以抽屉形式编辑名称、别名、摘要、类型专属字段和富文本补充说明。

### 主区上方：事实关系图

关系图默认展示项目中的全部实体节点和事实关系。没有关系的实体仍作为孤立节点出现，但 schema 类别、predicate 节点和 schema 连线不进入默认图：

```text
林遥 ─工作于→ 档案管理局 ─位于→ 雾城
  └────────试图改变────────→ 记忆规则
记忆规则 ─约束→ 档案管理局
```

关系图只负责浏览、选择和筛选，不支持拖线创建、直接改边或删除关系。

点击图节点后：

- 突出当前节点及其相关边；
- 下方关系清单只显示该节点的传入和传出关系；
- 显示“清除筛选”，恢复全部事实。

点击图中空白区域也会清除筛选。Ontology 类别、关系类型定义和 schema 语句不出现在默认事实图中。

### 主区下方：事实关系清单

关系清单是事实关系唯一的增删改入口。默认展示全部事实；点击目录实体或图节点后自动筛选。

每条关系由以下内容组成：

```text
源实体 | 关系类型 | 目标实体 | 操作
林遥   | 工作于   | 档案管理局 | 编辑 / 删除
```

新增关系使用清单内的编辑行。用户先选择关系类型，界面依据 Ontology 的源类型和目标类型约束过滤可选实体。保存前再次执行完整校验。

关系图与关系清单由同一份事实语句派生，不分别保存图形数据和表格数据。

### 独立入口：Ontology 管理

Ontology 不占据世界事实主界面。工作区提供独立的“Ontology 管理”入口，用于维护：

- 关系类型的稳定 ID 和显示名称；
- 允许的源实体类型；
- 允许的目标实体类型；
- 可选的反向关系；
- 关系类型来源：系统核心或项目自定义；
- 项目自定义关系类型的启用状态。

系统核心关系类型只读。项目可以创建和停用自定义关系类型。已经被事实引用的关系类型不能直接删除；停用后保留历史事实，但不能用于新增关系。

## 统一图数据模型

Ontology 与事实物理合并到同一套节点和语句中，逻辑上通过 `kind` 区分。

```ts
type WorldClassNode = {
  id: string;
  kind: 'class';
  label: string;
};

type WorldEntityNode = {
  id: string;
  kind: 'entity';
  label: string;
  classId: string;
  attributes: Record<string, unknown>;
};

type WorldPredicateNode = {
  id: string;
  kind: 'predicate';
  label: string;
  scope: 'system' | 'project';
  status: 'active' | 'inactive';
};

type WorldNode = WorldClassNode | WorldEntityNode | WorldPredicateNode;

type WorldStatementKind = 'schema' | 'fact';

type WorldStatement = {
  id: string;
  kind: WorldStatementKind;
  subjectId: string;
  predicateId: string;
  objectId: string;
};
```

同一张图中的 schema 与 fact 示例：

```text
工作于 ─源类型→ 角色             schema
工作于 ─目标类型→ 组织           schema
工作于 ─反向关系→ 雇佣           schema
林遥   ─工作于→ 档案管理局       fact
```

类型、实体和关系类型都具有稳定 ID。重命名只改变节点标签，不改变语句引用。

首期不为事实关系加入时间范围、强度、公开程度等限定属性。如果未来出现这类需求，再为 statement 增加 qualifier，或把复杂关系提升为事件实体；首期不提前引入该复杂度。

## 实体数据

实体仍保留上一版确认的结构化属性：

- 通用字段：名称、别名、一句话摘要、富文本补充说明；
- 地点：地点类型、上级地点、时代、环境特征；
- 组织：组织目标、权力范围、所在地；
- 角色：角色资产引用、世界身份；
- 规则：适用范围、触发条件、产生效果、代价、例外。

这些字段通过实体属性抽屉编辑。富文本是补充语料，不自动成为正式事实关系。

## 数据流与校验

### 新增事实

1. 用户在事实关系清单点击新增；
2. 用户选择关系类型；
3. 系统读取该 predicate 的 schema 语句；
4. 系统按照源类型和目标类型约束过滤实体选项；
5. 用户选择源实体和目标实体；
6. 保存前校验节点存在性、关系类型状态、源目标类型、自关联限制和重复事实；
7. 校验成功后写入一条 `kind: 'fact'` 的 statement；
8. 事实关系图和关系清单同时从最新 statement 集合重新派生。

### 选择和筛选

1. 页面初始状态不设置实体筛选；
2. 图谱和清单展示全部事实；
3. 点击目录实体或图节点后设置 `selectedEntityId`；
4. 图谱突出相关节点和边；
5. 清单筛选 `subjectId` 或 `objectId` 等于当前实体的事实；
6. 清除筛选后恢复全量事实。

### 删除保护

- 删除实体前检查全部 fact statement 和实体字段引用；
- 删除或停用项目关系类型前检查事实引用；
- 系统核心关系类型不可修改或删除；
- 已停用项目关系类型仍能解析和展示历史事实；
- 完全相同的源实体、关系类型和目标实体不能重复保存；
- schema 不合法或引用悬空时禁止新增事实，并显示具体约束错误。

## AI、RAG 与关系图

AI 和 RAG 不依赖人工填写关系描述，而是从事实语句生成稳定上下文：

```text
林遥是角色。
林遥工作于档案管理局。
档案管理局位于雾城。
记忆规则约束档案管理局。
```

实体检索文档由实体结构化属性、富文本补充说明，以及该实体的传入和传出事实共同生成。关系类型标签和必要的 Ontology 约束可以作为元数据进入索引，但 schema statement 不作为普通世界事实混入生成文本。

关系图只读取 `kind: 'fact'` 的 statement。Ontology 推理和约束校验读取 `kind: 'schema'` 的 statement。两者共享节点 ID 和 predicate ID。

## 组件边界

- `StoryWorldviewWorkspace`：维护知识图状态、目录选择和筛选状态；
- `StoryWorldviewFactGraph`：只读渲染事实节点和连线，发出节点选择与清除筛选事件；
- `StoryWorldviewFactLedger`：新增、编辑、删除事实关系，显示 Ontology 校验结果；
- `StoryWorldviewEntityDrawer`：编辑实体结构化属性和富文本补充说明；
- `StoryWorldviewOntologyManager`：独立维护项目关系类型，展示只读核心关系；
- 领域模型模块：管理节点、schema/fact statement、派生查询、上下文生成和完整性校验。

图组件不拥有事实数据；关系清单不自行维护图形状态；Ontology 管理器不直接修改事实。所有组件通过领域模型的稳定接口读写统一知识图状态。

## 错误处理

- 无可用关系类型时，新增关系入口不可用，并引导进入 Ontology 管理；
- 关系类型停用、schema 悬空或类型约束冲突时保留当前草稿；
- 保存失败不修改最后一次有效事实集合；
- 图布局失败时退化为关系清单，不阻塞事实编辑；
- 当前筛选实体被删除后自动清除筛选；
- 空图显示创建实体和事实关系的明确入口，不显示无意义的空白画布。

## 测试与验收

### 领域测试

- schema 与 fact statement 可以共存并正确区分；
- 关系类型的源类型、目标类型和启用状态约束事实保存；
- 核心关系只读，自定义关系可创建和停用；
- 重命名实体或 predicate 不破坏事实引用；
- 实体和 predicate 删除保护覆盖全部引用；
- AI/RAG 上下文只把 fact 序列化为世界事实。

### 组件测试

- 默认图谱和清单展示全部事实；
- 点击目录实体或图节点后只显示相关传入、传出关系；
- 清除筛选恢复全量事实；
- 图谱不提供新增、编辑或删除边的入口；
- 清单可以新增、编辑和删除事实；
- 非法源类型或目标类型无法保存；
- Ontology 管理入口与事实编辑入口分离；
- 实体属性抽屉不会替代事实关系主工作区。

### 浏览器验收

- 桌面端同时呈现目录、事实图和事实清单；
- 移动端按目录、事实图、事实清单顺序纵向排列；
- 清单编辑控件在窄屏下不发生横向溢出；
- 图布局异常时清单仍可编辑；
- 页面无运行时错误或警告。

## 首期范围外

- 在关系图中拖线创建或直接编辑边；
- 把 Ontology schema 节点混入默认事实图；
- 从富文本静默生成正式事实；
- 时间、强度、秘密程度等 statement qualifier；
- 自动 Ontology 推理、冲突修复和关系合并；
- Server、数据库、向量索引和多人协作接入。
