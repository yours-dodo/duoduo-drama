# Onboarding 创作空间选择设计

## 背景

当前 `/onboarding` 直接展示团队空间创建表单。产品入口需要先让用户选择个人创作空间或团队创作空间，避免用户在尚未明确创作上下文时直接进入团队命名流程。

## 目标

- `/onboarding` 提供个人创作空间和团队创作空间两个卡片入口。
- 选择个人创作空间后直接进入 `/workspace`。
- 选择团队创作空间后进入独立的团队选择页。
- 团队选择页提供加入团队和创建团队两个卡片。
- 加入团队本次仅作为不可用占位入口，明确标注“即将开放”。
- 创建团队继续复用现有团队名称表单和创建接口。

## 非目标

- 本次不实现加入团队、邀请码或团队邀请流程。
- 本次不修改个人空间、团队空间的数据模型或服务端接口。
- 本次不改变 `/workspace` 及现有创作工作台的业务行为。

## 路由与交互

### `/onboarding`

页面展示两个可点击卡片：

- “个人创作空间”：使用普通链接进入 `/workspace`。
- “团队创作空间”：使用普通链接进入 `/onboarding/team`。

页面保留认证门禁、站点布局和 onboarding 的现有视觉基调，但不再直接展示团队创建表单。

### `/onboarding/team`

页面展示两个卡片：

- “加入团队”：使用不可交互的语义元素或禁用卡片呈现，并显示“即将开放”。不触发导航或请求。
- “创建团队”：进入 `/onboarding/create-team`。

### `/onboarding/create-team`

迁移当前 `/onboarding` 的团队名称表单、校验、提交状态和错误处理。成功创建团队后继续进入 `/workspace`；失败时保留当前错误提示和重试能力。

旧的 `/app/onboarding` 兼容重定向继续指向 `/onboarding`，不新增旧路径逻辑。

## 实现边界

- 每个路由使用独立的 Astro 页面文件，避免用客户端状态模拟多步流程。
- 复用 `BaseLayout` 和 `AuthGate`，使认证、站点头部、页脚和无障碍语义保持一致。
- 复用并扩展 onboarding 页面样式，不引入新的客户端 UI 框架。
- 可点击卡片使用真实 `<a>` 元素；加入团队占位卡片使用不可点击元素，并提供视觉与文案状态。

## 测试与验收

- 静态检查三个页面的目标文案和链接：个人入口为 `/workspace`，团队入口为 `/onboarding/team`，创建团队入口为 `/onboarding/create-team`。
- 验证加入团队卡片没有导航行为，并展示“即将开放”。
- 验证创建团队表单仍提交 `POST /api/v1/teams`，成功后进入 `/workspace`，错误时保留错误提示。
- 运行 Web 相关测试、typecheck 和 build；按项目要求在桌面和窄屏宽度检查 `/onboarding` 与 `/onboarding/team`。
